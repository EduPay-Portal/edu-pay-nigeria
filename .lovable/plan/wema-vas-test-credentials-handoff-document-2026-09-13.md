# Wema VAS Test Credentials Handoff Document

Create `WEMA_HANDOFF.md` at the project root — a ready-to-send sheet for the Wema Bank integration team containing everything their onboarding checklist requires.

## Contents

1. **Base URL** — single Functions base URL with a clearly marked `[PASTE FROM LOVABLE BACKEND PANEL]` placeholder (project URLs are never printed in chat; the user copies it once from Project Settings → Backend).

2. **Authentication** — static Bearer token on every request, header format `Authorization: Bearer <WEMA_VAS_BEARER_TOKEN>`. Placeholder for the token value (the user pastes the same value they saved in the secure form — it is never exposed to chat by design). Note that requests without/with a wrong token get HTTP 401 `{"status":"96","status_desc":"Unauthorized"}`.

3. **Vendor-hosted endpoints** (all `POST`, `Content-Type: application/json`):
   - `/wema-account-lookup` — Account Lookup
   - `/wema-transaction-notification` — Transaction Notification
   - `/wema-mini-statement` — Mini Statement (last 10 days, credits + debits)
   - `/wema-kyc-details` — KYC Details
   - `/wema-block-account` — Block Account
   Each documented with sample request body and sample success/failure responses exactly as implemented.

4. **Test virtual accounts** — the 711-prefixed accounts generated by the retire & reissue flow, with a note that the full list is pulled from the Virtual Accounts admin screen after reissue runs (placeholder rows for 3–5 sample accounts).

5. **Status codes used** — `00` success, `07` invalid/inactive account, `96` temporary/unauthorized.

6. **Provisioning notes** — static accounts (no `amount` in lookup), vendor-name-first account naming (`ASCI/Student Name`), BVN/NIN returned from student profile with institution fallback.

7. **Open items Wema must confirm** — unpublished schemas for Mini Statement / KYC / Block Account, production prefix, Transaction Search URL + token, static vs dynamic accounts.

## Technical details

- Single new file `WEMA_HANDOFF.md` at repo root; no code, schema, or secret changes.
- Content derived from the already-deployed functions (`wema-account-lookup`, `wema-transaction-notification`, `wema-mini-statement`, `wema-kyc-details`, `wema-block-account`) so samples match real behavior.
- No real secret values written into the file — placeholders only.
- User fills in exactly two placeholders (base URL, bearer token) before sending to Wema.
